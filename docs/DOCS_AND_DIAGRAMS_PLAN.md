# ParkingOS Docs & Diagrams — Agent Execution Plan

Goal: close documentation gaps without code changes.

## 0a. Code-to-diagrams approach (mandatory for all diagram tasks)

Diagrams are GENERATED from checked-in text sources — never hand-drawn binaries.

- Source of truth: `docs/diagrams/*.d2` (D2 language, https://d2lang.com).
  ER tables use D2 `sql_table` shapes.
- Rendered artifacts: `docs/diagrams/*.svg`, generated by
  `scripts/render_diagrams.sh` (requires `d2`; install:
  `curl -fsSL https://d2lang.com/install.sh | sh`). Re-run the script after
  every `.d2` change and commit source + SVG together.
- Markdown docs embed the SVG: `![title](diagrams/<name>.svg)`.
- Mermaid fenced blocks are a fallback ONLY when a diagram must render inline
  on GitHub without SVG support; do not maintain both for the same diagram.
- Acceptance per diagram: `.d2` source exists, SVG is freshly rendered
  (script exits 0), SVG is referenced from its doc.

## 0. Conventions (ALL agents must follow)

- Paths: `docs/<name>.md`, diagrams embedded as `mermaid` fenced blocks inside those docs. No external renderer required.
- Ubiquitous language — must match `CONTEXT.md`: `Garage`, `Garage access`,
  `Operational access`, `Archived garage`, `Active garage`, `Ticket`,
  `Active parking session`. NEVER `site/branch/location/visit/booking`.
- Sources of truth to read FIRST before writing:
  - `README.md`, `CONTEXT.md`, `pom.xml`
  - `src/main/java/com/parking/model/*.java`
  - `src/main/java/com/parking/enums/*.java`
  - `src/main/java/com/parking/services/*.java`
  - `src/main/java/com/parking/persistence/PersistenceStore.java`
  - `src/main/java/com/parking/config/AppConfig.java`
  - `src/main/java/com/parking/security/*.java`
  - `src/main/java/com/parking/gui/shell/AppShell.java`, `gui/*View.java`
  - `src/test/java/com/parking/**`
- Definition of Done per doc: markdown exists, facts cite `file:line`,
  `mvn test` unaffected, no secrets added.
- Relevant skills in `.agents/skills/` (invoke before starting):
  - `mattpocock/grill-with-docs` or `mattpocock/grill-me` — clarify scope per doc.
  - `mattpocock/research` — capture findings as cited markdown.
  - `mattpocock/writing-for-agents` — keep docs pointer-friendly for agents.
  - `mattpocock/tdd` — only if a doc task requires touching code (should not).
